# Native FileInput panel presentation

Three unmodified CUA app-window JPEGs record the pinned public FileInput chooser
in its unselected, single-selected and multiple-selected states. Go to Folder
navigated to the controlled fixtures. The horizontal column scrollbar was then
set to its right end so the task-owned entries were visible. Selection used an
ordinary click and Command-click; Open delivered both URLs in browser order
while the native panel was still visible.

The native panel includes a sidebar, back/forward and view controls, a location
menu, search, column navigation, and selection preview. Single and multiple
selection expose different preview presentations. These are explicit missing
surfaces in the current Linux prototype; its existing path field alone is not
an accepted equivalent. CUA supplies lossy JPEG bytes. These files retain those original bytes with the
correct extension; they are neither cropped nor re-encoded and do not provide
a lossless strict raster baseline. The initial PNG signature check failed and
exposed the format mismatch before sealing.

Only filtered AX text is retained: structural roles, panel controls and
controlled fixture entries. The raw screenshots contain ordinary OS sidebar
labels and task-owned ancestor folder names. They are observations of this
configured host, not portable defaults to hard-code into the Linux sidebar.

The existing helper reuses the recorded source-built library. Helper inputs,
binary hash, native panel flags, source callback trace, fixture configuration
and host versions are retained. The first launch used an incorrect executable
name and exited 127; its log is retained alongside the corrected invocation.
No Swift source or native executable is tracked in Avelino.

This record does not close exact artwork, the full panel context matrix,
physical input/display, reader or independent source replay acceptance.
