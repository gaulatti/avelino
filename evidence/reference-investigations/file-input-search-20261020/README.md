# FileInput positive search observations

These are controlled projections of CUA accessibility observations from the
pinned desktop reference. They are not raw AX-tree archives, a fresh independent
library replay, or native acceptance evidence. Apple helper sources and binaries
remain outside the Linux repository; their build records and hashes are retained.

For the one-word `avelinoulnacerulean` control, the raw query exposes both the
name-matching file and `pine-only.txt`, whose contents contain the token. Choosing
Name Contains through Down/Return produces the Filename token and exposes only
the name-matching file. The earlier long query also exposes an uppercase name,
a matching directory, and a nested file. Current-folder mode retains the nested
file. This proves the observed content/name distinction and recursive inclusion;
it does not prove general matching semantics, ranking or cross-folder exclusion.

The recorded scope radio buttons are authoritative for the observed UI state.
The Where label can still say Searching “This Mac” while current-folder is selected.
Busy indicators were exposed; query completion was not verified. Clearing search
returns to the original controlled folder after rebinding the application to
recover its accessibility tree.

Open stays disabled after selecting the search result. A fresh plain-text helper
also leaves Open disabled for ordinary keyboard and Go to Folder selection.
Do not derive a search-specific eligibility rule or a permission diagnosis from
these failures. No owner result is observed. Coordinate input routing failed
`noWindowsAvailable`; these observations use indexed CUA controls and keys.

The sibling control was created after the initial query and was not observed in
global results; its queried Spotlight metadata was null. That does not establish
index readiness or scope exclusion. No indexing or permission settings changed.
All fixture bytes are controlled task data and are retained unchanged.
