# Date editor sizing analysis

A tiny Linux Qt consumer measures the installed, unchanged producer18 module at
all 1,848 native caller dates, including each locale/calendar/control font size.
The same input/output bytes repeat exactly in a fresh process. The measurement
uses DateRangeTools plus Qt TextMetrics; it does not render a complete date control
or close the whole-image, display-session, packaging or reader gates.

Native complete intrinsic widths remain constant in all 23 measured contexts.
The current owned editor's label advances vary in 10 contexts: Arabic, Persian,
Hebrew and Islamic contexts and their measured size variants. Figure-space padding
in a single text layout does not establish numeric column geometry across scripts.
Named and algorithmic labels also require reserved field widths. Font advances,
reserved fields, chrome and pixel-snapped frames need separate implementation.

summary.json keeps native complete intrinsic dimensions separate from Qt text
advances. The getter's shortDateString is also measured verbatim in Qt so font
advance differences can be inspected; it is not treated as a visible-editor oracle.
The earlier unsupported versioned module import and empty QJSValue JSON result
are retained with their failed validation. The final helper converts its JS value
before serialization and rejects an empty document.

The source widths, exact cold/retained PNGs, public accessibility bounds and fresh
355-file native source replay with supplemental style input are in the corresponding reference investigation.
The current module's 599 compiled core hashes and 148 consumer hashes remain
unchanged. No product code, reference, approved exception or tolerance changes.
All 401 previously retained strict raster failures remain open. Desktop coverage
remains 76/80 candidates and 0/80 accepted; the four pending desktop entries and
separate 46-entry TV phase are unchanged.
