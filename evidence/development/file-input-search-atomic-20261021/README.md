# Atomic token document mechanism

Three isolated Qt 6.8.3 prototypes preserve independent token metadata in inline QTextDocument object formats. Neither production project is mounted and no Avelino type is changed or registered. Both plain-text and rich-text variants run in offscreen/software; the plain-text property retains the native-style U+FFFC objects.

Prototype1 passes 14 phases per variant, including multiple tokens, drafts in all positions, forward deletion, replacement and Undo/Redo. Its bare C++ item exposes no accessible interface. Prototype2 runs the same 14 phases in a QML host: an accessible text interface exists, but no editable interface is detected; restored token selection and long-line scrolling are unresolved there. Prototype3 passes 24 phases per variant after adding an editable-text adapter, token selection metadata keyed to public document Undo positions, and an owned horizontal viewport. It verifies restored selection, caret visibility and return to the start, assistive replacement/Undo/Redo with another token intact, read-only/disabled rejection, and Unicode IME preedit/commit between tokens. Qt still creates and groups the actual text commands.

Sources, commands, raw logs/reports and two diagnostic PNGs per attempt are checksummed. The compiled binaries remain external with recorded hashes. These are mechanism observations, not a product build, installed-consumer run, real reader test or native equivalence. All production integration, lifecycle, command-path, menu/child accessibility, display-session, scaling, raster, physical and independent-machine gates remain open. Do not promote these receipts into acceptance.
